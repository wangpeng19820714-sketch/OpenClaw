# Learnings Log

Captured learnings, corrections, and discoveries. Review before major tasks.

---

- 2026-03-22: Jenkins Lobster HMAC requests must send the JSON payload with `curl --data-binary @file`. Using `curl -d @file` changes the body semantics enough to fail `X-Lobster-Content-SHA256` validation in `extensions-custom/lobster-release/http.ts`.
- 2026-03-22: In `GameXpert_Godot` local-path Jenkins builds, `rsync --exclude 'build/'` also strips `client/android/build`. That removes Godot Android export templates from the workspace and causes false "Android build template missing" failures. The safe form is anchoring root excludes like `/build/` plus a CI-side fallback that restores `client/android/build` from Godot `android_source.zip`.
- 2026-03-22: On this machine, port `18789` is served by the installed `openclaw-gateway` process, not the repo-local `node scripts/run-node.mjs gateway` process. Restarting a local dev gateway without stopping the live app does not change lobster-release behavior, so live validation may require patching the running plugin data store or restarting the actual app-managed gateway.
- 2026-03-22: Historical `lobster-release` records can keep stale `manifestUrl` values after route changes. Because patch baseline resolution reuses stored release/baseline metadata, a published baseline like `1.2.9` may need its stored `manifestUrl` and `patch_baselines.record_json.baselineManifestUrl` corrected before later patch releases can download the baseline manifest successfully.
- 2026-03-22: `GameXpert_Godot` should upload artifacts into per-build immutable subdirectories (for example `releases/<appVersion>-<buildNumber>-<shortCommit>/...`). Scanning a shared upload root causes `uploaded_artifacts.json` to include stale files from older builds and makes release manifests non-deterministic.
- 2026-03-22: `lobster-release` approval must be idempotent for an already-published release. Re-approving the same release should not rewrite `channel_state.previousReleaseId` to the current release, or regenerated manifests will produce a self-referential `rollbackTarget`.
- 2026-03-22: Repo Vitest includes do not cover `extensions-custom/**`. `corepack pnpm exec vitest run extensions-custom/lobster-release/*.test.ts` reports "No test files found", so `lobster-release` regressions need either a Vitest config update or targeted `tsx` scripts until the include list is expanded.
- 2026-03-22: When adding repo-wide test support for a custom extension, update both `vitest.config.ts` and `vitest.extensions.config.ts`. Only fixing the main include list still leaves `pnpm test:extensions` blind to `extensions-custom/**`.
- 2026-03-22: A Vitest positional filter like `vitest run --config vitest.extensions.config.ts "extensions-custom/**/*.test.ts"` can still report "No test files found" even when the config include list covers that path. For a reliable `pnpm test:extensions-custom` script, use a dedicated scoped config instead of depending on the CLI filter argument.
- 2026-03-22: CI scope detection must explicitly treat `extensions-custom/**` as node/windows scope. Otherwise PRs that only touch custom extensions can skip the main test workflows even if `vitest.extensions.config.ts` already includes them.
- 2026-03-22: When moving local secrets into an ignored `.env`, never replace the whole file blindly. Merge new keys into the existing `.env` or write a dedicated `.env.local`-style file first, or you can wipe unrelated local secrets and only recover the template structure from `.env.example`.
- 2026-03-22: Jenkins `start/publish/finish` callbacks may send `baselineVersion: ""` even when trigger-time baseline resolution already computed a real version. `lobster-release` must treat blank callback values as missing and preserve the existing build baseline, or live provenance and manifests regress from `1.2.x` to an empty baseline.
- 2026-03-22: In `GameXpert_Godot` Jenkins scripts, `load_env_file()` originally used plain `source`, which creates shell variables but does not export them to child processes. Python-based Lobster callback scripts then saw `PATCH_BASELINE_VERSION=""` even though `lobster_baseline.env` had a value. Using `set -a; source ...; set +a` fixes the export boundary.
- 2026-03-26: Repeated Jenkins callbacks are not naturally idempotent. Without explicit guards, duplicate `publish` callbacks insert duplicate artifacts, later `start/publish` callbacks can regress a terminal build back to `building/uploaded`, and a duplicate `finish` callback can knock a published release back to `awaiting_approval`. The safe fix is monotonic build status transitions, artifact identity dedupe, and a terminal-result no-op in `recordBuildFinish()`.
- 2026-03-26: Patch validation in `lobster-release` has to distinguish between local and remote artifact metadata. Local patch publishes can strictly validate `patch_manifest.json` and reject conflicting `patch_list.json` paths, but Jenkins callback payloads may reference uploaded patch metadata that is not readable on the gateway host. In that case, validation should record a skipped result instead of failing the publish callback.
- 2026-03-26: The real `GameXpert_Godot` patch artifacts do not match the original design-doc schema. Live `manifest.json` uses `format_version/packages/raw_files`, and live `patch_list.json` uses `download_bundles/download_raw_files`. `lobster-release` patch validation has to support both the design schema and the real Jenkins schema, or a real patch conflict drill will fail for the wrong reason before conflict detection runs.
- 2026-03-26: The repo-local `release_notifications_drain -> agent:pm:main` chain is now validated in-process by starting the gateway from source and letting `pm` consume a live `lobster-release` outbox record. In the current `pm` session-bound setup, `release_notifications_render` still returns `mode=session_bound`, but the notifier uses the rendered `message` tool plan and then calls `release_notifications_ack` with a Feishu delivery note. This is the expected live behavior for the current `pm` configuration.
- 2026-03-27: `extensions-custom/*` was not part of the repo `pnpm` workspace, so adding `postgres` under `extensions-custom/lobster-release/package.json` did not actually install the driver. PostgreSQL-backed custom extensions need `extensions-custom/*` included in `pnpm-workspace.yaml`, or their runtime deps stay invisible even after `pnpm install`.
- 2026-03-27: `lobster-release` can bridge to PostgreSQL without an immediate full async runtime refactor by loading PostgreSQL tables into an in-memory cache on startup and serializing writes through a background queue. That is a valid first migration stage, but it is not the end state: lock/nonce/idempotency/outbox writes still need stronger transactional handling, and a later async direct-store refactor is still desirable.
- 2026-03-27: `lobster-release` CI callbacks do not reuse the generic signed callback headers. `/api/ci/v1/*` expects `X-Lobster-*` headers for HMAC mode, and even with HMAC disabled it still requires `x-lobster-nonce` for replay protection. Sending only the generic `x-nonce/x-signature` pair produces misleading `409 replayed nonce` failures during API drills.
- 2026-03-27: PostgreSQL rollback API drills need a compatibility-safe target. The first published release in a channel is treated as a `major` bump, so rolling back from a later patch release to that very first release correctly trips the `resourceProtocolVersion` guard. Use a later stable patch target when validating the happy-path rollback flow.
- 2026-03-27: Repeated PostgreSQL container drills should use a fresh schema name each run. Reusing a prior schema can leave version history behind and produce misleading validation failures like `version 0.1.0 must be greater than 1.0.1` even when the handler logic is correct.
